# GitHub Résumé Generator

Turn any GitHub username into a beautiful, printable, **vector-PDF** résumé — entirely in the browser. No backend, no signup, no tracking.

[![Vector PDF](https://img.shields.io/badge/PDF-vector%20%2F%20searchable-3B82F6)]() [![Tech](https://img.shields.io/badge/Vite-React%2018-FAFAFA)]() [![License](https://img.shields.io/badge/license-MIT-A1A1AA)]()

```
┌──────────────────────────────────────────────────────────┐
│  github.com/torvalds  →  torvalds-resume.pdf  (~42 KB)   │
│                                                          │
│  • True vector text  • Three themes  • A4 / Letter       │
│  • Avatar embedded   • 100 KB main bundle (gz)           │
└──────────────────────────────────────────────────────────┘
```

## Highlights

- **True vector PDF.** Generated by `@react-pdf/renderer` — selectable, searchable, prints sharp at any size. No `html2canvas`/`jsPDF` rasterization. A typical résumé is **40–60 KB**.
- **Single source of truth.** The on-screen preview and the exported PDF render from one shared `ResumeData` object. Three runtime-switchable themes (Modern Serif, Swiss Minimal, Dev Terminal) for both renderers.
- **One GraphQL query.** Profile, contributions, pinned + top repos, languages, organizations, and rate-limit info — all in one round-trip.
- **Token stays client-side.** Your GitHub PAT is stored in `localStorage` only and only sent to `https://api.github.com/graphql`.
- **Zero CLS, lazy PDF.** The A4 canvas reserves space while loading. The 1.4 MB `react-pdf` chunk is dynamically imported only when you click *Download PDF* — the home and resume routes ship in ~17 KB gzipped main JS.
- **Strict TypeScript.** `noImplicitAny`, `noUncheckedIndexedAccess`, ESLint `@typescript-eslint/no-explicit-any: error`. No `any` anywhere.

## Quickstart

Requirements: **Node ≥ 18**, **npm ≥ 9**.

```bash
# 1. Install
npm install

# 2. Download the OFL-licensed font .ttf files into public/fonts/
#    (they're not committed — fetched once from upstream releases)
bash scripts/fetch-fonts.sh

# 3. Run dev server
npm run dev          # http://localhost:5173
```

Then open `http://localhost:5173`, type a GitHub username, and you're done.

### Production build

```bash
npm run build        # TS check + Vite build → dist/
npm run preview      # serve dist/ on http://localhost:4173
```

### Quality gates

```bash
npm run typecheck    # tsc --noEmit
npm run lint         # eslint . --max-warnings 0
npm run format       # prettier --write .
```

## GitHub Personal Access Token

The app works **without a token** but the unauthenticated GitHub API limit is only 60 requests/hour shared across the whole IP, so anonymous use can hit "Rate limit exceeded" quickly.

**Generate one:** [github.com/settings/tokens/new](https://github.com/settings/tokens/new?scopes=public_repo,read:user&description=GitHub%20R%C3%A9sum%C3%A9)

**Required scopes (classic PAT):**
- `public_repo`
- `read:user`

That's it. **Don't** grant the full `repo` scope — the app warns you in the token dialog if you do, because it isn't needed.

The token is stored in `localStorage` under the key `gh_pat_v1` and is **only ever sent** to `https://api.github.com/graphql`. There is a runtime URL assertion in `src/github/client.ts` to keep this honest.

For dev convenience, you can also set `VITE_GITHUB_TOKEN` in `.env.local`:

```
VITE_GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

When set, this overrides the in-app token.

## Architecture

```
src/
├── resume/
│   ├── types.ts                # ResumeData (the contract)
│   ├── normalize.ts            # GraphQL → ResumeData
│   ├── ResumeView.tsx          # Screen renderer (HTML/Tailwind)
│   ├── sections/               # Header, Stats, Languages, Pinned, …
│   ├── pdf/
│   │   ├── ResumeDocument.tsx  # PDF renderer (@react-pdf/renderer)
│   │   ├── styles.ts           # StyleSheet.create() per theme
│   │   └── fonts.ts            # Font.register() of self-hosted .ttf
│   └── themes/                 # tokens + Modern Serif / Swiss / Dev Terminal
├── github/
│   ├── client.ts               # graphql-request + token validation
│   ├── queries.ts              # The single GraphQL query
│   └── rateLimit.ts            # UI helpers
├── components/                 # ResumePreview, TokenDialog, ThemeSwitcher, ExportBar, …
├── store/                      # zustand stores (token, prefs)
├── lib/                        # pdfDownload, urlToDataUrl, languageStats, format, useResize
├── routes/                     # Home, Resume
├── App.tsx                     # <Routes/>
└── main.tsx                    # QueryClient + Router bootstrap
```

The on-screen `<ResumeView>` and the PDF `<ResumeDocument>` both consume the same `ResumeData`. Themes are just data: `<ResumeView>` reads them via CSS variables; `<ResumeDocument>` reads them via `StyleSheet.create()`.

## Deploy

### Vercel (recommended — zero config)

1. Push the repo to GitHub.
2. [Import it into Vercel](https://vercel.com/new). Vite is auto-detected.
3. Done. The included `vercel.json` rewrites all unknown paths to `/index.html` so deep links like `/u/torvalds` work on a hard reload.

### GitHub Pages

A workflow at `.github/workflows/pages.yml` deploys the production build to GitHub Pages on every push to `main`. To enable:

1. In the repo settings → **Pages**, set the source to **GitHub Actions**.
2. The site will live at `https://<user>.github.io/<repo>/`. The workflow injects `VITE_BASE=/<repo>/` into the build.

## What's *not* used (and why)

- ❌ `html2canvas`, `jsPDF`, `react-to-pdf`, `html2pdf.js` — these all rasterize HTML. Output is heavy, blurry, and not selectable. We render PDF text directly with `@react-pdf/renderer`.
- ❌ Chart libraries — the language bar is plain SVG/`<View>` rectangles for total control and a smaller bundle.
- ❌ External font CDNs at runtime — fonts ship in `public/fonts/` (Inter v4 + IBM Plex Serif + JetBrains Mono, all OFL-licensed).
